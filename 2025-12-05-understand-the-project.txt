  Project Overview

  This is a video monitoring system designed to detect unsafe or
  non-compliant activities of locomotive pilots (train drivers) from video
  footage. It uses computer vision and AI to identify multiple types of
  activities that could indicate safety concerns.

  Core Architecture

  Main Components:

  1. locopilot_monitor.py (5073 lines) - The main monitoring engine
  2. YOLOv8-Pose Adapter - Provides pose estimation for multiple people
  3. Image Preprocessing Service - Enhances frames for better detection
  4. Configuration Management - Environment-based settings
  5. FastAPI Web Service - REST API for video processing

  Key Technologies:

  - YOLOv8 - Object detection (phones, books, backpacks, persons)
  - YOLOv8-Pose - Multi-person pose estimation (body keypoints)
  - MediaPipe FaceMesh - Face landmark detection and eye tracking
  - OpenCV - Video processing
  - FastAPI - Web API framework
  - Multiprocessing - Parallel video processing for performance

  Activity Detection Capabilities

  The system detects 10 types of activities:

  1. Cell Phone Usage (Type 2) - Detects phone near hands/ears
  2. Microsleep (Type 3) - Eyes closed for 5+ seconds
  3. Sleep (Type 4) - Eyes closed for 30+ seconds or head down
  4. Writing/Logging (Type 5) - Writing in logbook while train is running
  5. Packing Bags (Type 6) - Hands near backpack/luggage
  6. Group Detected (Type 7) - More than 2 people present
  7. LP Hand Gesture Failure (Type 8) - Loco Pilot doesn't exchange hand
  gesture when ALP does
  8. ALP Hand Gesture Failure (Type 9) - Assistant LP doesn't respond to
  LP's gesture
  9. Mind Diversion (Type 10) - Head turned away from controls
  10. No Person Detected (Type 11) - Empty frame (no pilot visible)

  How It Works

  1. Video Sampling

  - Configurable FPS: Default 0.5 FPS (1 frame every 2 seconds) for
  efficiency
  - Smart Frame Sampling: Processes 1/60th of frames for 30 FPS video
  - Performance: ~60x faster than real-time processing

  2. Multi-Person Detection Pipeline

  Frame Input
      ↓
  YOLOv8-Pose (multi-person pose estimation)
      ↓
  Person Role Identification (LP/ALP/Others)
      ↓
  ROI-Based Detection (8 regions per person):
      - Hands (wrists) - for phone/writing
      - Hips (lap area) - for books
      - Ears - for phone calls
      - Torso - for objects
      ↓
  MediaPipe FaceMesh (eye closure detection)
      ↓
  Activity Analysis (temporal filtering)
      ↓
  Evidence Clip Generation

  3. Detection Methods

  Object Detection (ROI-based):
  - Creates 180px radius regions around body keypoints
  - Batch YOLO inference for 4x performance improvement
  - Aspect ratio validation to filter false positives

  Pose-Based Detection:
  - Writing: Wrists close together + hands below shoulders + head looking
  down
  - Sleep: Head tilt < -100° + minimal movement + stable posture
  - Hand Gestures: Wrist above shoulder + sustained raise (2+ seconds)
  - Packing: Hand near backpack with sustained proximity (4+ seconds)

  Temporal Filtering:
  - Consecutive Frames: Requires multiple detections before triggering
  - Grace Periods: Allows brief interruptions without resetting detection
  - Suppression: Work activities suppress false positive hand gestures

  4. Multi-Person Tracking

  - Per-Person Activity Tracking: Maintains separate state for each
  individual
  - Role-Based Analysis: Differentiates LP (Loco Pilot) vs ALP (Assistant
  LP)
  - Coordination Detection: Detects when one pilot gestures but the other
  doesn't respond
  - Deduplication: Removes duplicate person detections using IoU threshold

  5. Performance Optimizations

  Batch ROI Processing (locopilot_monitor.py:1102):
  # Single YOLO call for all ROIs instead of N sequential calls
  # 1200ms → 300ms for 8 ROIs per person
  batch_detections = self.detect_objects_in_rois_batch(...)

  Multiprocessing (app/utils/video_multiprocessing.py):
  - Splits video into 6-second chunks
  - Processes chunks in parallel across CPU cores
  - Optimized for 11-core systems

  Memory Management:
  - Context managers for video capture cleanup
  - Explicit frame deletion after processing
  - Garbage collection after video processing

  Output Artifacts

  For each detection, the system creates:

  1. Video Clips - 5 seconds before and up to 60 seconds of activity
  2. Annotated Frames - Frames with bounding boxes and pose landmarks
  3. Activities JSON - Structured data with timestamps and metadata:
  {
    "tripId": "TRIP-123",
    "crewName": "John Doe",
    "activityType": 2,
    "des": "Using mobile phone",
    "startTime": "00:01:23",
    "endTime": "00:01:35",
    "fileUrl": "https://example.com/evidence/clip_001.mp4"
  }

  Configuration

  Highly configurable via environment variables:
  - Detection Thresholds: Confidence levels for each activity
  - Temporal Windows: Required consecutive frames, grace periods
  - Preprocessing: CLAHE, gamma correction, noise reduction
  - Performance: Multiprocessing workers, chunk sizes, sampling rate

         """Fast quality metric based on brightness variance"""

         variance = np.var(gray)
         mean = np.mean(gray)

         # Good quality: high variance, reasonable brightness

     Implementation 3: Motion-Based Frame Skipping

     File: locopilot_monitor.py

     Add to class:
     class LocopilotActivityMonitor:
         def __init__(self, ...):
             self.previous_frame_gray = None
             self.motion_threshold_low = 5.0   # Skip if motion < 5
             self.motion_threshold_high = 50.0  # Increase sampling if > 50

         def calculate_motion_score(self, current_frame):
             """Calculate frame-to-frame motion using mean absolute 
     difference"""
             current_gray = cv2.cvtColor(current_frame, cv2.COLOR_BGR2GRAY)

             if self.previous_frame_gray is None:
                 self.previous_frame_gray = current_gray
                 return 100.0  # Process first frame

             # Calculate absolute difference
             diff = cv2.absdiff(current_gray, self.previous_frame_gray)
             motion_score = np.mean(diff)

             self.previous_frame_gray = current_gray
             return motion_score

         def should_process_frame(self, frame, frame_idx):
             """Decide if frame should be processed based on motion"""
             motion = self.calculate_motion_score(frame)

             # Always process every Nth frame as baseline
             if frame_idx % (self.step * 4) == 0:
                 return True, "baseline"

             # Skip very static frames
             if motion < self.motion_threshold_low:
                 return False, "static"

             # Process high-motion frames
             if motion > self.motion_threshold_high:
                 return True, "high_motion"

             # Normal processing
             return True, "normal"
