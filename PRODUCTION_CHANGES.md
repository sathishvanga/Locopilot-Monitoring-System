# Production Deployment Changes Summary

## Overview
Modified the Locopilot Monitoring System for production server deployment with automatic cleanup of uploaded videos and optimized storage usage.

## Changes Made

### 1. ✅ Automatic Video Cleanup
**File:** `app/controllers/video_controller.py`

**Before:**
```python
# Schedule cleanup of uploaded video (optional)
# Uncomment to enable automatic cleanup after processing
# background_tasks.add_task(
#     video_processing_service.cleanup_uploaded_video,
#     video_path
# )
```

**After:**
```python
# Schedule cleanup of uploaded video after processing (production mode)
background_tasks.add_task(
    video_processing_service.cleanup_uploaded_video,
    video_path
)
```

**Impact:** Uploaded videos are now automatically deleted after processing completes, preventing disk space accumulation.

---

### 2. ✅ Temporary Upload Directory
**File:** `app/utils/config.py`

**Before:**
```python
upload_dir: str = "uploads"
```

**After:**
```python
upload_dir: str = os.getenv("UPLOAD_DIR", "/tmp/locopilot_uploads")  # Use temp dir for production
```

**Impact:** Uploads now go to `/tmp` directory by default, which is automatically cleaned by the OS. Can be overridden via `UPLOAD_DIR` environment variable.

---

### 3. ✅ Disable Clip Generation by Default
**File:** `app/controllers/video_controller.py`

**Before:**
```python
saveClips: Optional[bool] = Form(default=True, description="Generate video clips and images (default: true)")
```

**After:**
```python
saveClips: Optional[bool] = Form(default=False, description="Generate video clips and images (default: false for production)")
```

**Impact:** By default, only `activities.json` is generated (no video clips or images), significantly reducing storage usage. Clients can still request clips by setting `saveClips=true`.

## Storage Behavior Comparison

### Before (Development Mode)
❌ Uploads → `uploads/` → **Kept indefinitely**
✅ Activities JSON → `locopilot_evidence/run_*/activities.json` → Saved
✅ Video Clips → `locopilot_evidence/run_*/clips/` → **Always generated**
✅ Frame Images → `locopilot_evidence/run_*/frames/` → **Always generated**

### After (Production Mode)
✅ Uploads → `/tmp/locopilot_uploads/` → **Auto-deleted after processing**
✅ Activities JSON → `/opt/poc2/output/run_*/activities.json` → Saved
❌ Video Clips → **NOT generated by default** (optional with `saveClips=true`)
❌ Frame Images → **NOT generated by default** (optional with `saveClips=true`)

## Environment Variables Reference

### Required for Production
```bash
# Directories
UPLOAD_DIR=/tmp/locopilot_uploads           # Temp upload directory
OUTPUT_DIR=/opt/poc2/output                  # Evidence output
LOG_DIR=/opt/poc2/logs                       # Application logs

# Processing
ENABLE_MULTIPROCESSING=true                  # Enable parallel processing
MP_MAX_WORKERS=8                             # Number of worker processes
MP_CHUNK_DURATION=6                          # Chunk duration in seconds
SAMPLE_FPS=0.5                               # Sample at 0.5 FPS

# Models
YOLO_WEIGHTS=yolo11s.pt                      # YOLO model file
PRELOAD_OCR=1                                # Preload OCR model
```

### Optional
```bash
# Override defaults
DEBUG=false
CORS_ORIGINS=*
MAX_UPLOAD_SIZE=524288000                    # 500 MB
```

## Summary of Benefits

### 🎯 Storage Efficiency
- **Before:** ~500MB video + ~100MB clips + ~50MB images = **~650MB per request**
- **After (default):** ~500MB video (deleted) + ~100KB JSON = **~100KB retained per request**
- **Savings:** **~99.98% storage reduction** per request

### ⚡ Performance
- Multiprocessing enabled by default
- CPU-only PyTorch (faster deployment, no CUDA overhead)
- Optimized chunk size for parallel processing
- Headless OpenCV (no X11 dependencies)

### 🔒 Security
- Temp directory for uploads (OS-managed cleanup)
- Automatic cleanup after processing
- Configurable via environment variables
- Ready for production hardening

### 📊 Operational
- Systemd service with auto-restart
- Comprehensive logging
- Health check endpoints
- Easy deployment and updates
- Detailed documentation
