  Step 1: Define Your Classes

  Step 2: Annotate with CVAT or Label Studio (Recommended)

  Option A: CVAT (easiest, browser-based)
  pip install cvat-cli
  # Or use the hosted version at https://app.cvat.ai (free)
  1. Go to app.cvat.ai → Create account
  2. Create a Project → define your label classes
  3. Create a Task → upload your 10 frames from frames/
  4. Draw bounding boxes around each object
  5. Export annotations as YOLO 1.1 format

  Option B: LabelImg (lightweight desktop app)
  pip install labelImg

  1. Set save format to YOLO (button on left sidebar)
  2. Create your class list when prompted
  3. Draw bounding boxes → Save (each image gets a .txt file)

  Option C: Roboflow (best for augmentation)
  1. Go to roboflow.com → upload frames
  2. Annotate in browser
  3. Export in YOLOv8 format (compatible with YOLO26/Ultralytics)

  Step 3: Organize Dataset

  After annotation, structure your data like this:
  dataset/
  ├── data.yaml
  ├── train/
  │   ├── images/
  │   │   ├── frame_1146.jpg
  │   │   ├── frame_1305.jpg
  │   │   └── ...
  │   └── labels/
  │       ├── frame_1146.txt    # annotation per image
  │       ├── frame_1305.txt
  │       └── ...
  └── val/
      ├── images/
      │   └── ...
      └── labels/
          └── ...

  Each .txt label file has one line per object:
  # class_id  x_center  y_center  width  height  (all normalized 0-1)
  0 0.512 0.341 0.15 0.42
  1 0.723 0.556 0.03 0.05

⏺ How YOLO Label Format Works

  Each line in the .txt file represents one object with 5 numbers:

  class_id  x_center  y_center  width  height

  All coordinates are normalized (0.0 to 1.0), meaning they are fractions of the
   image size, NOT pixel values.

  Breaking Down Each Line of frame_6879.txt

  Let's go line by line. The image is 1280x720 pixels.

  ---
  Line 1: 0 0.52 0.33 0.28 0.52 — Person (LP, on phone)

  ┌───────┬──────────┬─────────────────────────┬─────────────────────┐
  │ Field │  Value   │         Meaning         │      In Pixels      │
  ├───────┼──────────┼─────────────────────────┼─────────────────────┤
  │ 0     │ class_id │ person (from data.yaml) │ —                   │
  ├───────┼──────────┼─────────────────────────┼─────────────────────┤
  │ 0.52  │ x_center │ 52% from left edge      │ 0.52 × 1280 = 666px │
  ├───────┼──────────┼─────────────────────────┼─────────────────────┤
  │ 0.33  │ y_center │ 33% from top edge       │ 0.33 × 720 = 238px  │
  ├───────┼──────────┼─────────────────────────┼─────────────────────┤
  │ 0.28  │ width    │ 28% of image width      │ 0.28 × 1280 = 358px │
  ├───────┼──────────┼─────────────────────────┼─────────────────────┤
  │ 0.52  │ height   │ 52% of image height     │ 0.52 × 720 = 374px  │
  └───────┴──────────┴─────────────────────────┴─────────────────────┘

  So the bounding box goes from:
  - Left = (0.52 - 0.28/2) × 1280 = 486px
  - Right = (0.52 + 0.28/2) × 1280 = 845px
  - Top = (0.33 - 0.52/2) × 720 = 50px
  - Bottom = (0.33 + 0.52/2) × 720 = 425px

  That's the green box around the LP (back person) in the image above.

  How to Verify I Did It Correctly

  1. Look at the visualized/ folder — each image shows the boxes drawn on top.
  Check if boxes tightly wrap each object.
  2. Quick mental check formula:
    - x_center = 0.5 means the box is centered horizontally
    - y_center = 0.5 means the box is centered vertically
    - Small width/height (like 0.04) = small object (phone, cup)
    - Large width/height (like 0.38) = large object (person)
  3. Common issues to look for:
    - Box too big (covers background) → width/height too large
    - Box off-center (not covering the object) → x_center/y_center wrong
    - Wrong class ID → check data.yaml mapping

  Looking at our visualized images, the boxes are reasonable but not 
  pixel-perfect — my visual estimates from the overhead CCTV angle have some
  slack. For production training you'd want to tighten them in a tool like CVAT
  where you can drag the box edges precisely.
