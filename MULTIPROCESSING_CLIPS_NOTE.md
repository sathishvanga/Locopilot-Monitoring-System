# Multiprocessing: Activity Clips Behavior

## Overview

When using **multiprocessing**, video clips and images **ARE NOW GENERATED** by default! Workers save clips directly to the shared clips directory during parallel processing.

You can **optionally disable** clip generation for maximum speed by setting `saveClips=false`.

---

## Behavior

### Both Single-Process and Multi-Process Modes

✅ **Clips ARE generated by default** (since latest update)

```
locopilot_evidence/
  run_20251111_120000/
    activities.json
    processing_state.json
    clips/
      video_writing_frame00000100_000_clip.mp4    ← Clip files exist!
      video_writing_frame00000100_000_activity.jpg
      ...
```

**activities.json:**
```json
{
  "activityClip": "/full/path/to/clips/video_writing_frame00000100_000_clip.mp4",
  "activityImage": "/full/path/to/clips/video_writing_frame00000100_000_activity.jpg"
}
```

### Optional: Disable Clips for Maximum Speed

⚡ **Set `saveClips=false` to skip clip generation**

```bash
curl -X POST "http://localhost:8000/api/v1/video/process" \
  -F "video=@video.mp4" \
  -F "tripId=TRIP-001" \
  -F "useMultiprocessing=true" \
  -F "saveClips=false"  # ← Disable clips for max speed
```

Result: No clips saved, only activity metadata

## How Clips Are Generated (Updated Implementation)

### With Clips Enabled (Default)

1. **Workers save clips directly**: Each worker has access to shared run directory
2. **Unique filenames**: No conflicts since filenames include frame numbers
3. **Parallel I/O**: Workers write clips concurrently (thread-safe)
4. **Full paths stored**: Activities contain absolute paths to clips

### Optional: Disable for Performance

When `saveClips=false`:
1. **Memory Efficiency**: Workers don't keep frame data after processing
2. **I/O Reduction**: No disk writes during parallel processing  
3. **Speed Boost**: ~10-20% faster without clip generation
4. **Metadata only**: Activity JSON contains paths but no files

### Trade-offs

| Mode | Speed | Clips | Use Case |
|------|-------|-------|----------|
| `saveClips=true` (default) | Fast | ✅ Yes | Most use cases |
| `saveClips=false` | Fastest | ❌ No | Metadata-only, dashboards |

- ❌ Slower (3-5x slower than multiprocessing)
- ❌ Not recommended for production

## Current Implementation

### What's Stored in activities.json

```json
{
  "fileUrl": "/path/to/original/video.mp4",         // ✅ Full path to source video
  "activityStartTime": "10.00",                     // ✅ Start time in seconds
```

## FAQ

### Q: Why are clip paths stored if files don't exist?

**A:** For consistency and future clip generation. The paths indicate where clips would be saved if generated.

### Q: Can I generate clips after multiprocessing?

**A:** Not currently implemented. You would need to:
1. Re-process the video with single-process mode, OR
2. Extract clips manually using FFmpeg with stored timestamps

### Q: Do I need clips for activity detection to work?

**A:** No! Activities are detected and stored regardless. Clips are just visual evidence.

### Q: How do I check if clips exist?

```python
import os

def check_clip_exists(activity):
    clip_path = activity.get('activityClip')
    if clip_path and os.path.exists(clip_path):
        return True
    return False
```
